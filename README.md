# Data Structure Course Design: 智能校园/景区导览系统

本工程是一个由 AI Agent 团队（Member A, B, C）协作开发的综合性数据结构课程设计项目。系统旨在提供校园或景区内的路径规划、旅游推荐、全文检索及数据压缩等核心功能。

---

## 👥 团队分工与角色

本项目由三位 Agent 成员组成，各司其职并遵循严格的接口契约。

| 成员 | 角色定位 | 核心职责 | 负责模块 |
| :--- | :--- | :--- | :--- |
| **Member A** | **项目大总管 & 算法中枢** | 负责图结构基础设施、路径规划算法实现（最短路径、多目标规划）及室内外导航逻辑。 | `src/graph/`, `src/routing/` |
| **Member B** | **业务逻辑 & 交互专家** | 负责推荐系统（Top-N）、模糊查询、排序算法及用户交互流程的组织。 | `src/search/`, `src/recommend/` |
| **Member C** | **数据集成 & 质量保障** | 负责基础数据准备、全文检索（Trie/倒排索引）、数据压缩及系统集成测试。 | `data/`, `tests/`, `src/compress/` |

## 🔄 协作流程与规范

为了确保 Agent 之间的高效协同，我们遵循以下工作流：

### 1. 任务启动阶段
- **同步远程仓库**：每次开始工作前，必须执行 `git pull`（或 `git pull --rebase`）确保本地代码与远程 `main` 分支完全一致，防止进度脱节。
- **进度对齐**：在开始任何工作前，优先检查 `工作进度/` 文件夹下对应周次的任务要求。
- **环境检查**：确认当前分支及依赖库状态，确保环境配置正确。

### 2. 开发与实施规范
- **接口优先**：修改任何跨模块调用的接口前，必须先更新 `docs/项目代码骨架与职责划分.md` 并通知相关成员。
- **原子提交**：遵循 Angular 提交规范（`feat:`, `fix:`, `docs:`, `test:`），确保每次提交只解决一个明确的问题。
- **代码自测**：在编写重要逻辑（如核心算法）后，需立即在 `tests/` 目录下编写或更新对应的单元测试。

### 3. 集成与验证
- **防冲突检查**：合并代码前，需检查是否与其他成员的接口存在矛盾，特别是节点 ID 的唯一性及门节点（Gate）的映射关系。
- **回归测试**：由 Member C 牵头定期进行集成测试，确保各模块联动正常。

---

## 🛠 技术标准

- **编程规范**：遵循 Python PEP 8 规范，强调类型提示（Type Hinting）和详细的文档字符串（Docstrings）。
- **数据一致性**：所有地理空间数据必须符合 `数据字典.md` 中的定义。
- **性能指标**：推荐算法需支持 Top-N 剪枝，路径规划需支持动态权重调整。

## 📅 每周同步节奏

1. **周初**：Member A 发布本周任务清单。
2. **周中**：接口对齐与初步联调。
3. **周末（周日 20:00 前）**：各成员在 `工作进度/对应周文件夹/` 内提交工作内容陈述（命名规范：`memberX第N周工作内容陈述.md`）。
4. **周日晚**：Member A 汇总周报。
