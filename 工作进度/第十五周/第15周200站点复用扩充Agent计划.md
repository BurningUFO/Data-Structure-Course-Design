# 第15周 200 站点复用扩充 Agent 计划

## 目标

在三天验收前，把站点数量从现有 21 个逐步扩展到 200 个。扩充方式优先采用“模板校园图”方案：新站点在外部接口、UI 站点选择器、搜索/推荐/路线响应中使用自己的 `site_id` 和学校名称，内部图数据复用已有可用校园的课程配置。

BNU 试点结论：`BNU` 可以不创建 `data/sites/BNU/`，通过 `template_site_id=THU` 复用 `THU` 的 outdoor、indoor、搜索记录、推荐距离和路线图；UI 默认只展示本地 GeoJSON 模板校园图，不加载真实瓦片底图，也不加载真实 OSM buildings/water/landuse 上下文图层。

## 单站 Agent 操作步骤

1. 启动前检查分支与脏工作区。

   ```bash
   git status --short --branch
   git branch --show-current
   ```

   分支必须是 `main`。如果不是 `main`，立即停止并报告。不要暂存、提交、删除或整理用户已有无关脏文件。

2. 选择一个模板站点。

   优先从现有 21 个可用站点里挑一个内部结构接近、节点命名稳定的模板。当前已跑通模板：

   - `THU`：适合作为北京高校模板，包含 `gate_north`、`library`、`canteen` 等常用验收节点。
   - 后续可按地区或学校类型分配其他模板，但必须先单站 smoke。

3. 在 `data/global_sites.json` 添加一个站点注册项。

   字段模板：

   ```json
   {
     "id": "NEW_SITE_ID",
     "name": "学校中文名",
     "description": "学校中文名模板校园站点，复用 TEMPLATE_SITE_ID 内部课程图配置，用于第15周 200 站点扩充；UI 默认展示无真实底图的模板校园图。",
     "location": "学校地址",
     "is_available": true,
     "data_status": "template_clone_available",
     "map_profile": "template_clone",
     "template_site_id": "TEMPLATE_SITE_ID",
     "display_overrides": {
       "node_names": {
         "gate_north": "学校北门",
         "library": "学校图书馆",
         "canteen": "学生食堂"
       },
       "user_names": {
         "template_user_001": "学校学习访客",
         "template_user_002": "学校校园游访客",
         "template_user_003": "学校食堂体验访客"
       },
       "text_replacements": {
         "模板大学": "学校中文简称",
         "模板图书馆": "学校图书馆",
         "模板食堂": "学生食堂"
       }
     },
     "sub_graphs": [
       "outdoor",
       "indoor_LIB",
       "indoor_TB1",
       "indoor_DORM1",
       "indoor_CANTEEN_TAOLI",
       "indoor_MAIN_BUILDING"
     ]
   }
   ```

   `sub_graphs` 必须与模板站点真实存在的 JSON 文件一致。使用 `THU` 作为模板时保持上面这组值；如果换模板，先读取该模板在 `global_sites.json` 里的 `sub_graphs` 并原样复制。

   `display_overrides` 是模板复用站点的必填展示层配置：

   - `node_names` 按稳定 `node_id` 覆盖用户可见地点名，不改变底层路线 ID。
   - `user_names` 按模板用户 `user_id` 覆盖用户选择器和兴趣上下文里的可见用户名；运行时可生成新增站点自己的用户 ID，但不要修改 `data/users.json`。
   - `text_replacements` 替换边名、描述、室内建筑名、路线步骤中的模板学校词汇。
   - 后续 agent 至少要覆盖 `gate_*`、`library`、`canteen`、`teaching_building`、`main_building`、`dormitory_1`、`sports_ground` 和常见路口名。
   - 验证时搜索结果、地图标注、路线起终点、室内建筑名、用户选择器和兴趣推荐上下文都不能继续显示模板学校原名。

4. 不创建真实地图目录。

   单站复用任务默认不创建：

   - `data/sites/NEW_SITE_ID/`
   - `data/sites/NEW_SITE_ID/geo/`
   - 任何真实 OSM roads/buildings/water/landuse 文件

   运行时由 `template_site_id` 解析到模板站点目录。

5. 单站 smoke 验证。

   用服务层或 HTTP API 验证下面接口。所有业务响应对外 `site_id` 必须是新增站点 ID，而不是模板站点 ID。

   ```text
   GET /api/bootstrap?site_id=NEW_SITE_ID
   GET /api/map/geojson?site_id=NEW_SITE_ID
   POST /api/search/scenic
   POST /api/search/places
   POST /api/recommend/catering
   POST /api/route
   POST /api/route/multi
   ```

   推荐路线 smoke：

   ```json
   {"site_id":"NEW_SITE_ID","start_node_id":"gate_north","target_node_id":"library"}
   ```

   推荐多目标 smoke：

   ```json
   {"site_id":"NEW_SITE_ID","start_node_id":"gate_north","target_node_ids":["library","canteen"],"return_to_start":false}
   ```

   推荐场所查询 smoke：

   ```json
   {"site_id":"NEW_SITE_ID","category":"catering","center_node_id":"gate_north","radius_m":3000,"limit":3}
   ```

   说明：部分模板在默认 500m 附近半径下可能成功但为空；验收 smoke 需要证明 alias 数据能返回结果，因此统一使用 3000m 半径。

6. UI 人工检查。

   - 站点选择器出现新增学校中文名。
   - 切换后地图不空白。
   - 地图状态或说明显示“模板校园图”。
   - 不显示真实底图，不显示真实 OSM buildings/water/landuse 图层。
   - 查询、推荐、路线结果可返回，且结果 `site_id` 为新增站点 ID。
   - 用户选择器不显示模板站点用户名；切换用户后兴趣推荐上下文里的 `user_name` 也不显示模板站点用户名。

BNU 的运行时规则：

- 外部请求与响应使用 `BNU`。
- 图、搜索记录、推荐距离和路线计算读取 `THU` 文件。
- 地图、搜索结果、路线步骤和室内建筑摘要使用 BNU 的 `display_overrides` 展示名，不直接暴露清华地点名。
- 用户选择器使用 BNU 运行时用户 ID 和 BNU 展示名，例如 `user_bnu_001` / `北师大学习访客`；`template_user_id` 仅用于追溯原模板用户。
- bootstrap 中 `map_capabilities.basemaps.default` 为 `none`。
- bootstrap 中 `map_capabilities.basemaps.modes` 只有 `模板校园图`。
- `/api/map/osm-layers?site_id=BNU` 成功返回空 FeatureCollection，不报告缺文件错误。

## 并行扩充分工

并行 agent 适合做“候选站点信息整理”和“单站 smoke”，但不适合同时写同一个 `data/global_sites.json`。

推荐流程：

1. 主 agent 维护一个待扩站点清单，分配唯一 `id/name/location/template_site_id`。
2. 子 agent 只产出单站 JSON 片段和 smoke 记录，不直接合并全局注册表。
3. 主 agent 分批把 JSON 片段合并进 `data/global_sites.json`，每批 10 到 20 个站点。
4. 每批合并后运行批量 registry 校验，检查 ID 唯一、模板存在、sub_graphs 文件存在。
5. 每批抽样 2 到 3 个站点跑完整 API smoke。

## 禁止事项

- 不要批量复制 `data/sites/<template>/` 目录。
- 不要让运行时 UI 直接调用 OSMnx、Overpass 或外部地图采集接口。
- 不要给模板复用站点声明真实 OSM buildings/water/landuse 可用。
- 不要把业务响应里的 `site_id` 改成模板站点 ID。
- 不要改动路由核心算法来适配模板站点。
- 不要让多个 agent 同时编辑并提交 `data/global_sites.json`。
- 不要暂存或提交 `.DS_Store`、`.playwright-cli/`、`.codex_tmp/` 或用户已有无关文档脏文件。

## 最终合并规则

每批进入主线前至少满足：

- `data/global_sites.json` 是合法 JSON。
- 新增站点 ID 全局唯一。
- 每个模板站点存在于 `global_sites.json`。
- 每个 `sub_graphs` 项对应的模板站点 JSON 文件存在。
- 抽样站点的 bootstrap、GeoJSON、搜索、推荐、单目标路线、多目标路线全部成功。
- UI 抽样确认“模板校园图”文案出现，且没有真实底图误导。
- UI 抽样确认用户选择器和兴趣推荐上下文不显示模板站点用户名。

验收前三天的优先级：

1. 数量达标：注册表达到 200 个可选站点。
2. 单站可用：每个新增站点至少能通过服务层 smoke。
3. UI 不误导：模板站点必须显示模板校园图，不加载真实 OSM 上下文。
4. 文档可追溯：每批保留新增 ID、模板 ID、验证结果。
