  1. 主业务链路贯通：当前已可从标准分层数据中查询校园节点，并结合真实距离完成推荐排序与统一响应输出。

3. 成员详细工作汇报

【Member A：图结构与路径规划】

本周主要成果：

  1. 交通工具过滤逻辑落地：在 src/routing/router.py 中支持 allowed_transports、transport_modes、transport_mode、blocked_transports 与 vehicle_access 字段，能够根据步行、车辆等偏好过滤不可通行边。
  2. 多目标路径基础版实现：新增 query_multi_target(...)，采用点对点最短路径预计算与状态压缩 DP，支持多个目标点访问顺序规划和分段路径拼接。
  3. 标准分层数据 loader 完成：在 src/graph/loader.py 中新增 GraphLoader.load_site_graph(site_id="PKU", ...)，可直接读取 data/sites/{site_id}/outdoor.json 与 indoor_*.json，并自动补充室外门节点与室内入口节点之间的 gate_link。
  4. 接口语义统一：将 site_id 作为可选参数接入 query_routing(...)、query_distance(...)、query_multi_target(...)，并明确 shortest_time 返回秒数。
  5. 真实数据验证完成：已使用 PKU 标准分层数据验证单目标路径、跨层路径和多目标路径逻辑。

【Member B：查询、排序与推荐业务】

本周主要成果：

  1. 业务服务层拆分：新增 src/search/search_service.py，将查询、过滤、距离补充、推荐排序和统一响应组织为 search_and_recommend(...) 主入口。
  2. 距离接口正式接入：新增 src/search/distance_adapter.py，封装 Member A 的 GraphLoader 与 Router.query_distance(...)，使业务层无需直接依赖 A 模块内部细节。
  3. 距离排序能力补齐：新增 src/recommend/ranking.py，支持 distance_m 升序推荐，并将缺失、不可达或异常距离统一排在可计算距离之后。
  4. 统一 Response 增强：更新 src/search/response.py，成功与失败响应均支持 metadata，可展示排序策略、距离单位、距离状态统计和结果字段说明。
  5. CLI 演示入口更新：更新 src/search/cli_demo.py，支持输入关键字、类别、起点节点、排序字段和返回数量，默认基于标准分层真实数据展示完整链路。

【Member C：数据测试与系统集成】

本周主要成果：

  1. 数据目录规范化：新增并维护 data/global_sites.json、data/sites/PKU/outdoor.json、data/sites/PKU/indoor_LIB.json，形成当前标准分层数据结构。
  2. 数据字典升级：将 docs/数据字典.md 升级为 v2.0，补充全局景区、节点字段、边字段、跨模块依赖关系、门节点规则和历史兼容说明。
  3. 字段补充适配联调：为边补充 vehicle_access 字段，支持 A 侧交通工具过滤；为节点补充 tags、category、description 等字段，支持 B 侧查询推荐。
  4. 旧数据兼容口径锁定：为 data/成员Cdata/scenic_spots.json 补充 map_node_id 字段，校园条目映射到标准图节点，全国景区统一置为 null 并由 B 侧返回 missing_node_id。
  5. 联调问题跟踪完成：维护《三模块联调问题跟踪表》，记录并关闭 C-001 至 C-008，明确 destination 字段不参与当前路径/距离计算。
