# 第八周具体工作任务要求 (4月20日 - 4月26日)

> **本周核心目标**：本周是项目的**“系统联调与链路贯通周”**。在第七周各模块独立开发并完成单元测试的基础上，本周必须完成三方代码的首次真实数据集成。同时，推进进阶算法的预研和业务链路的扩展。

---

## 1. 核心协作目标

- **数据与接口对齐**：统一数据标准，解决由于第七周数据存放不规范及接口字段未对齐带来的潜在风险。
- **全链路联调**：打通 `输入关键字 -> 景点查询过滤 -> Top-K 结合真实距离排序 -> 返回统一响应结构` 的完整业务流。

---

## 2. 成员具体任务要求

### 【成员 A：图结构与路径规划负责人】
*   **本周核心任务**：
    1.  **进阶算法预研（多目标规划）**：启动用户游览多个景点的最优路线（简化版 TSP 问题）调研设计。
    2.  **交通工具过滤逻辑**：扩展现有的图搜索逻辑，支持根据不同的交通工具偏好过滤/剪枝不支持通过的边（例如：机动车禁行区域的绕行）。
    3.  **配合联调与接口释疑**：协助 Member B 接入 `query_distance` 接口，明确返回值的单位量纲（距离与时间）；配合验证距离逻辑在真实数据中的表现。
*   **提交要求**：
    - 提交多目标规划的初步代码或设计文档。
    - 配合完成联调，响应其他成员提出的接口调整需求。

### 【成员 B：查找、排序、推荐与业务负责人】
*   **本周核心任务**：
    1.  **整合距离排序**：正式接入成员 A 的 `query_distance` 接口，在现有的推荐结果中加入基于真实距离的排序或距离字段展示。
    2.  **完善业务服务层**：在 `src/search/` 和 `src/recommend/` 之间补充更稳定的业务服务层，梳理代码架构。
    3.  **主链路复用与扩展**：基于跑通的景点推荐链路，尝试将同样的查询架构复用到后续的美食推荐和场所查询中。
    4.  **真实数据验证**：使用 Member C 整理好的学校/景区数据验证现有的基础查询逻辑。
*   **提交要求**：
    - 提交整合了真实距离计算的 Top-K 推荐代码。
    - CLI 演示脚本需能展示包含距离信息和统一响应结构的完整搜索推荐结果。

### 【成员 C：数据、测试、系统集成负责人】
*   **本周核心任务**：
    1.  **规范数据目录与字典更新（紧急）**：将第七周新增在 `data/成员Cdata/` 下的文件移动并整合至标准的 `data/` 根目录。同步更新 `docs/数据字典.md`，彻底拉齐 A 模块（图结构）与 B 模块（业务推荐）对数据的字段依赖。
    2.  **主导三模块联调**：牵头组织 A 和 B 联调主链路（查景点 → 推荐并附加距离 → 路线规划初探），跟踪并记录出现的接口兼容性问题。
    3.  **补充缺失数据字段**：根据 B 模块业务查询和 A 模块交通工具过滤的新需求，在测试数据中补充相应的缺失字段。
*   **提交要求**：
    - 规范化后的 `data/` 目录结构。
    - 提交更新后的 `docs/数据字典.md` v2.0。
    - 在本周目录下提交一份《三模块联调问题跟踪表》。
