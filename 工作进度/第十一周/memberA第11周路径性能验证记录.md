## 2. 验证方法

本次验证使用当前仓库内置 Python 环境直接调用 `Router`，不新增缓存文件，不修改路由接口。

测试方法：

1. 加载 `GraphLoader.load_site_graph("PKU")`。
2. 创建 `Router(graph)`。
3. 每个场景预热 10 次。
4. 每个场景正式重复 300 次。
5. 统计 `avg`、`p95`、`max` 耗时，单位为毫秒。
6. 同时记录路径总距离和预计时间，确认结果不是空跑。

当前环境未识别 `py` 启动器，因此验证命令统一采用 `python -B`。

## 4. 结论

1. 在 58 节点 / 原始 200 边规模下，单目标 Dijkstra 查询耗时稳定在毫秒以下，满足第11周 Web 展示和答疑演示需要。
2. 多目标路径采用点对点最短路预计算 + 状态压缩 DP，3 个目标点场景平均耗时约 1 到 2 ms，可支撑当前验收演示。
3. 跨层路径、交通方式过滤、最短距离 / 最短时间策略均可在 200 边数据规模下正常返回稳定字段。
4. 当前验证不将耗时写入自动化测试断言，避免不同机器性能波动导致测试不稳定；自动化测试只验证路径结果、字段和课程规模口径。
