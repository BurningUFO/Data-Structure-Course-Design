# 第十一周具体工作任务要求（5月11日 - 5月17日）

> **本周核心目标**：本周是项目的 **“课程硬指标补齐与正式产品骨架锁定周”**。第十周已经完成全文检索、压缩、统一输出深化和最小可演示 Web UI，本周必须围绕新的总计划推进：**第 13 周（2026-05-25 至 2026-05-31）必须产出可运行、可使用、有精美 UI 的正式产品**，第 14-15 周只用于用户体验优化与验收收口。因此，第十一周不能再把关键功能和课程硬性要求继续后移，必须开始系统性补齐数据规模、日记管理、AIGC 轻量演示、Web 主入口骨架和课程要求覆盖清单。

---

## 1. 本周总体完成标准

对照 `docs/软件开发任务.md`、`docs/课程要求覆盖清单.md` 和最新总计划，本周结束时至少需要满足以下标准：

1. **Web 主入口成为统一骨架**：浏览器端已具备首页、站点切换、主导航、帮助入口和核心页面跳转，不再依赖 CLI 才能串起主链路。
2. **课程硬指标开始收口**：完成 `>=10` 用户样例、课程要求覆盖清单、数据规模补齐方案和第一轮核验记录，不能继续停留在“后续再说”。
3. **日记管理不再只有查询**：至少具备创建、编辑、删除、评分和媒体占位的业务入口或 UI 表单。
4. **AIGC 动画生成确定为可演示方案**：明确输入、输出和页面入口，允许采用模板化动画、分镜页或 GIF，但不能只保留文档描述。
5. **接口冻结开始执行**：A、B、C 三侧对第 13 周前必须使用的核心接口完成第一轮收口，新增字段优先追加，不允许频繁改协议。

## 2. 本周核心协作目标

### 2.1 第13周正式产品倒计时启动

第十一周起项目进入“第 13 周正式产品”倒计时，所有成员都需要从“补功能原型”切换到“补课程硬要求 + 锁产品形态”。

本周至少要做到：

- 明确第 13 周前必须可演示的全部功能入口。
- 把课程原文中的硬性要求和仓库里的现有实现逐项对齐。
- 形成一份对内统一使用的缺口清单，避免成员各自理解不一致。

### 2.2 Web 骨架与主链路收口

成员 B 牵头把第十周最小可演示 UI 升级为正式产品骨架，成员 A、C 配合接入路径、多目标、日记管理和数据统计信息。

本周至少要做到：

- 首页、站点选择、主导航和帮助入口可用。
- 站点切换后，查询、路径和高亮状态能重置。
- 主链路 `查景点/推荐 -> 路径规划 -> 场所/美食 -> 日记检索` 继续保持可运行。

### 2.3 课程硬指标与验收材料底座

成员 C 牵头把课程要求中的“数据规模、用户数、文档项、AIGC、用户说明、评价改进意见”转化为可核验的项目清单。

本周至少要做到：

- 建立并维护课程要求覆盖清单。
- 补齐 `>=10` 用户样例。
- 形成 200+ 景区/校园推荐对象与核心导航站点的拆分方案说明。
- 明确第十二周的数据达标验证口径和测试方式。

## 3. 成员具体任务要求

### 【成员 A：图结构与路径规划负责人】

**本周核心任务：**

1. **路径接口第一轮冻结**
   - 基于现有 `query_routing(...)`、`query_distance(...)`、`query_multi_target(...)`，完成对外字段口径检查。
   - 明确业务层和 UI 展示必须依赖的字段，尽量在本周完成第一轮冻结。
   - 如需新增字段，优先采用追加方式，不破坏已有参数顺序和字段语义。

2. **多目标路径与室内导航的产品化接入准备**
   - 为成员 B 提供适合 Web 展示的多目标路径摘要、节点顺序、总距离/时间和路径步骤。
   - 检查室内导航、跨层路径、不可达路径在 UI 展示时需要的错误信息和提示字段。

3. **规模扩展与性能验证**
   - 配合成员 C 的数据扩充方案，验证 200+ 节点 / 边规模下的典型路径查询性能。
   - 形成至少一组“最短距离 vs 最短时间”和一组“单目标 vs 多目标”的演示样例。

4. **第11周答疑准备**
   - 围绕 2026-05-12 的课程答疑节点，整理路径规划模块当前可演示能力、当前限制和下一周风险点。

**提交要求：**

- 更新 `tests/test_routing.py` 或新增验证脚本，覆盖本周新增展示字段、不可达路径和多目标典型样例。
- 如接口字段有调整，必须同步更新 `docs/项目代码骨架与职责划分.md`。
- 提交 `工作进度/第十一周/memberA第11周工作内容陈述.md`。

本周推荐演示链路：

1. 浏览器启动后进入首页，展示站点选择、主导航和帮助入口。
2. 查询景点或学校，展示推荐结果，并从结果进入单目标路径规划。
3. 切换到多目标路径规划，展示访问顺序和总距离 / 总时间。
4. 进入日记中心，完成一次日记创建或编辑，再进行全文检索和评分展示。
5. 进入 AIGC 轻量演示入口，展示图片 + 文字描述的预览结果或模板化输出。
6. 切换站点或输入异常参数，确认页面能给出基础提示且状态正确重置。

## 5. 提交形式与流程

- **浏览器主入口优先**：第十一周新增能力优先在 Web UI 可见，CLI 仅作为回归和兜底入口。

- **文档同步**：若新增数据字段、测试命令、页面入口或演示方式，必须同步更新对应文档。

### 工作陈述提交

- **截止时间**：本周日（5月17日）20:00 前。
- **命名规范**：`memberX第11周工作内容陈述.md`。
- **最低内容**：本周完成事项、涉及文件、测试命令与结果、当前阻塞、下周计划、可演示入口或命令。
