# 第七周具体工作任务要求 (4月13日 - 4月19日)

> **本周核心目标**：从“静态数据加载”转向“动态逻辑运算”。成员 A 需交付核心路径规划算法，成员 B 需跑通首条业务链路，成员 C 需确保各模块接口的兼容性。

---

## 1. 核心协作目标
本周是“算法落地周”。**成员 A** 必须交付 Dijkstra 核心接口，以便 **成员 B** 在景点推荐结果中加入“距离排序”功能。**成员 C** 需同步更新测试数据，支持多场景测试。

---

## 2. 成员具体任务要求

### 【成员 A：图结构与路径规划负责人】
*   **本周核心任务**：
    1.  **实现 Dijkstra 核心算法**：在 `src/routing/` 目录下实现单目标最短路径算法。
    2.  **支持多策略切换**：
        - 策略一：**最短距离**（基于边权重 `distance`）。
        - 策略二：**最短时间**（基于 `distance / (speed * congestion)`）。
    3.  **交付距离查询接口**：向成员 B 提供 `query_distance(start_node_id, target_node_id)` 接口，用于辅助推荐排序。
*   **提交要求**：
    - 代码存放在 `src/routing/` 目录下。
    - 需包含 Dijkstra 算法的单元测试，验证在含有 10+ 节点和 20+ 边的图中，计算结果的准确性。

### 【成员 B：查找、排序、推荐与业务负责人】
*   **本周核心任务**：
    1.  **实现景点/学校查询逻辑**：支持按名称模糊查询、按类别过滤（如：教学楼、食堂、洗手间）。
    2.  **完成“查-排-推”闭环**：
        - 用户输入关键字 -> 系统过滤结果 -> 调用第六周实现的 Top-K 模块 -> 返回前 10 个最匹配（或热度最高）的景点。
    3.  **设计统一业务响应结构**：定义一套通用的 `Response` 模型（含 `success`, `data`, `message` 等字段），确保所有查询接口返回格式一致。
*   **提交要求**：
    - 代码存放在 `src/search/` 和 `src/recommend/` 目录下。
    - 编写一个简单的 CLI 交互脚本，演示“输入关键字返回 Top-10 景点”的过程。

### 【成员 C：数据、测试、系统集成负责人】
*   **本周核心任务**：
    1.  **启动三模块初步联调**：组织 A 和 B 确认 `query_distance` 接口的输入输出格式（如：是否包含 `site_id`，节点 ID 是否统一）。
    2.  **扩充全量测试数据**：在 `data/` 下增加更多节点（至少 50+）和边（至少 80+），覆盖室内外、孤立点等异常场景。
    3.  **接口文档 v1.0 维护**：更新 `docs/数据字典.md`，同步记录本周确定的核心 API。
*   **提交要求**：
    - 更新 `data/` 目录下的 JSON 文件。
    - 在 `工作进度/第七周/` 提交一份初步的《联调问题记录表》。
