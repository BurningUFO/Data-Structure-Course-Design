# 第九周具体工作任务要求（4月27日 - 5月3日）

> **本周核心目标**：本周是项目的 **“业务功能覆盖与期中检查准备周”**。第八周已经完成主链路首次联调和真实距离排序接入，第九周必须围绕 M2 里程碑补齐业务覆盖面，确保场所查询、美食推荐、日记基础查询、模糊查询和主链路演示均可运行，并形成可用于期中检查的说明材料。

---

## 1. 本周总体完成标准

对照 `docs/软件开发任务.md` 中 M2 里程碑，本周结束时必须满足以下标准：

1. **主链路保持可运行**：`查景点/场所 -> 推荐排序 -> 真实距离补充 -> 路径规划` 不得回退。
2. **业务覆盖补齐**：场所查询、美食推荐、日记基础查询、模糊查询均需有可运行入口和测试样例。
3. **标准数据继续统一**：新开发默认使用 `data/global_sites.json` 与 `data/sites/{site_id}/`，旧 `data/成员Cdata/scenic_spots.json` 仅作为历史兼容数据。
4. **期中检查材料可用**：每个成员需提交本模块的功能说明、演示入口、测试结果和当前限制。

---

## 2. 本周核心协作目标

### 2.1 业务功能覆盖

成员 B 牵头将第八周的 `search_and_recommend(...)` 主链路扩展到更多业务实体：

- 校园设施/场所查询。
- 美食或餐饮点推荐。
- 日记标题查询与目的地查询。
- 模糊查询增强，支持更真实的用户输入。

### 2.2 数据一致性收口

成员 C 牵头修正第八周遗留的数据一致性问题：

- `data/global_sites.json` 当前声明了 `indoor_DORM1`，但 `data/sites/PKU/` 下实际只有 `outdoor.json` 和 `indoor_LIB.json`。
- 本周必须选择一种方案收口：补齐 `indoor_DORM1` 文件，或从注册表中移除该声明，并同步更新 `docs/数据字典.md`。

### 2.3 中期演示准备

成员 A 负责算法说明和路径规划演示链路，成员 B 负责业务演示脚本，成员 C 负责测试记录和联调结果整理。周末前需要能用统一脚本或明确命令完成期中检查演示。

## 3. 成员具体任务要求

### 【成员 A：图结构与路径规划负责人】

**本周核心任务：**

1. **多目标路径规划增强**
   - 在第八周 `query_multi_target(...)` 基础上补充典型演示用例。
   - 明确当前状态压缩 DP 方案的适用规模、时间复杂度和限制条件。
   - 对不可达目标、重复目标、空目标列表等边界输入给出稳定响应。

2. **交通工具路径展示完善**
   - 保持已有 `vehicle_access` / `transport_mode` 过滤逻辑稳定。
   - 补充步行、车辆或自行车场景下的对比演示样例。
   - 确认不同交通工具下不可通行边会被正确过滤，并在测试中体现。

3. **配合业务扩展联调**
   - 支持成员 B 在场所查询、美食推荐中继续调用 `query_distance(...)`。
   - 如 B 侧需要 `query_routing(...)` 返回路径详情用于展示，应协助确认字段含义，不随意修改现有接口顺序。

4. **期中检查算法说明**
   - 整理成员 A 部分的算法说明草稿，至少包括 Dijkstra、最短时间权重、多目标状态压缩 DP、交通工具过滤。
   - 给出每个算法的输入、输出、复杂度和当前测试覆盖。

**提交要求：**

- 更新或新增 A 侧算法说明文档，可放入 `docs/` 或第九周工作进度目录。
- 补充 `tests/test_routing.py` 或独立测试脚本，覆盖多目标和交通工具典型场景。
- 提交 `工作进度/第九周/memberA第9周工作内容陈述.md`。

---

### 【成员 B：查找、排序、推荐与业务负责人】

**本周核心任务：**

1. **场所查询业务落地**
   - 基于标准分层数据中的节点字段，实现设施/场所查询。
   - 支持类别过滤，例如 restroom、catering、shopping、parking、education 等。
   - 支持按 `distance_m`、`heat`、`rating` 排序；涉及距离时继续通过 A 侧距离适配层计算真实路径距离。

2. **美食推荐链路落地**
   - 复用 `search_and_recommend(...)` 或抽象出同风格业务入口，完成餐饮/食堂/咖啡等美食推荐。
   - 支持 Top-K、类别/菜系过滤、距离排序。
   - 如标准数据暂未覆盖足够美食字段，应与成员 C 明确最低字段集，不自行硬编码不可维护字段。

3. **日记基础查询**
   - 在 `src/diary/` 下实现日记标题精确查询和目的地查询的最小可运行版本。
   - 支持按热度、评分排序日记结果。
   - 输出结构应尽量复用现有统一 Response 风格，避免日记模块单独发明一套返回格式。

4. **模糊查询增强**
   - 在已有 `src/search/fuzzy_search.py` 基础上补充更稳定的匹配策略。
   - 至少覆盖名称、标签、描述字段的模糊匹配。
   - 明确当前暂不支持的能力，例如拼音首字母、同义词扩展或编辑距离阈值。

5. **CLI / 演示入口扩展**
   - 更新 CLI 或新增第九周演示脚本，能展示以下链路：
     - 查询场所并按真实距离排序。
     - 查询美食并返回 Top-K。
     - 查询日记标题或目的地。
     - 从查询结果进入路径规划或距离展示。

**提交要求：**

- 更新 `src/search/`、`src/recommend/`、`src/diary/` 中对应业务代码。
- 补充 `tests/test_search.py`、`tests/test_recommend.py`，并新增 `tests/test_diary.py`。
- 提交 `工作进度/第九周/memberB第9周工作内容陈述.md`。

### 【成员 C：数据、测试、系统集成负责人】

**本周核心任务：**

1. **数据一致性修复**
   - 修正 `global_sites.json` 与 `data/sites/PKU/` 实际文件不一致问题。
   - 若保留 `indoor_DORM1`，必须补充对应 `data/sites/PKU/indoor_DORM1.json`，并保证节点 ID 全局唯一、门节点映射一致。
   - 若暂不建设宿舍室内图，则从 `sub_graphs` 中移除 `indoor_DORM1`，并在数据字典中说明当前仅支持图书馆室内图。

2. **补充业务数据字段**
   - 为 B 侧场所查询和美食推荐补足最低字段集。
   - 建议字段包括：`id`、`name`、`category`、`tags`、`description`、`site_id`、`node_id` 或 `map_node_id`、`heat`、`rating`。
   - 若需要餐饮扩展字段，可补充 `cuisine`、`avg_price`、`open_hours`。

3. **日记数据与检索准备**
   - 整理或补充日记测试数据，支持按标题、目的地、热度、评分查询。
   - 为后续全文检索和压缩模块预留字段，如 `content`、`destination`、`author_id`、`views`、`rating`、`tags`。
   - 本周只要求日记基础查询可用，全文检索和压缩可作为第10周重点。

4. **集成测试与期中检查记录**
   - 新增或整理 `tests/test_integration.py`，覆盖至少一条完整链路：
     `查询 -> 推荐 -> 距离计算 -> 路径规划`。
   - 记录第九周联调问题，必要时新增《第九周联调问题跟踪表》。
   - 汇总可运行命令、测试结果和当前限制，供周报与期中检查使用。

**提交要求：**

- 更新 `data/` 与 `docs/数据字典.md`，确保字段和目录口径一致。
- 补充集成测试或测试记录。
- 提交 `工作进度/第九周/memberC第9周工作内容陈述.md`。
