# 第十周具体工作任务要求（5月4日 - 5月10日）

> **本周核心目标**：本周是项目的 **“M3 联调能力预热与离线检索落地周”**。第九周已经完成 M2 所要求的业务覆盖和期中展示收口，第十周必须开始补齐课程设计中的**日记内容全文检索**、**无损压缩/解压**、**统一输出结构深化**与**算法对比初稿**，为第十二周的 M3 联调可演示节点做准备。

---

## 1. 本周总体完成标准

对照 `docs/软件开发任务.md` 中 M3 里程碑与课程设计硬性功能要求，本周结束时至少需要满足以下标准：

1. **M2 主链路不得回退**：`查景点/场所 -> 推荐排序 -> 真实距离补充 -> 路径规划` 继续保持可运行。
2. **日记全文检索具备最小可运行版本**：支持基于 `content` 字段的关键词检索，能够返回命中文档、匹配词项和基础排序结果。
3. **压缩模块具备最小可运行版本**：能够对标准日记文本或样例文本完成哈夫曼压缩、解压和一致性校验。
4. **统一输出继续收口**：日记基础查询、全文检索、场所查询、美食推荐在 CLI 或服务层中继续保持统一 Response 风格。
5. **算法与材料开始沉淀**：至少形成一份可继续扩展的算法对比初稿或验证记录，覆盖路径规划、检索或压缩中的核心方案。

---

## 2. 本周核心协作目标

### 2.1 日记全文检索落地

成员 C 牵头实现倒排索引全文检索的最小闭环，成员 B 负责把检索结果接入现有日记业务返回结构。

本周至少要做到：

- 支持对 `data/diary_data.json` 中的日记正文执行关键词检索。
- 支持返回 `diary_id`、`title`、`matched_terms`、`score` 等基础信息。
- 支持单关键词与多关键词的最小可用检索逻辑。
- 明确当前不支持或暂缓支持的能力，例如中文复杂分词、TF-IDF、短语查询、布尔查询等。

### 2.2 压缩与离线能力启动

成员 C 牵头在 `src/compress/` 下启动哈夫曼压缩能力，先完成**可验证的基础版**，再考虑与全文检索的离线联动。

本周至少要做到：

- 对日记文本或独立样例文本完成压缩和解压。
- 能验证解压结果与原文一致。
- 记录压缩前后大小、字符频率构建方式和当前压缩率表现。
- 若本周无法完成“压缩数据上的倒排索引”，必须在工作陈述中明确拆分方案和后续接入计划。

### 2.3 M3 联调基础收口

成员 A、B、C 共同为第十二周 M3 节点提前收口接口和演示方式，避免第十一周后期同时堆功能和联调。

本周至少要做到：

- 日记全文检索结果可以在业务层被展示，而不是停留在独立脚本。
- 现有路径规划接口继续稳定，支持“日记结果 -> 目的地节点 -> 路径规划”演示链路。
- 开始整理算法对比或策略对比材料，避免后期文档集中堆积。

## 3. 成员具体任务要求

### 【成员 A：图结构与路径规划负责人】

**本周核心任务：**

1. **路径策略对比准备**
   - 基于已有 `query_routing(...)`、`query_distance(...)`，整理 `shortest_distance`、`shortest_time`、不同交通工具过滤场景的对比样例。
   - 输出适用于演示或文档引用的典型用例，说明输入、输出、适用场景和当前限制。

2. **路径结果展示信息补强**
   - 在不破坏第八、九周接口顺序和核心字段命名的前提下，检查 B 侧展示是否还需要补充路径段说明、边名称、层级信息或策略说明。
   - 若需要新增展示字段，优先以**追加非破坏性字段**的方式实现，不得随意改动既有参数顺序。

3. **配合日记检索链路联调**
   - 支持 B/C 验证“全文检索到日记 -> 读取 `destination_node_id` -> 调用路径规划”链路。
   - 若标准日记数据的节点映射存在异常，需协助判断是数据问题还是路由接口问题。

4. **算法对比初稿启动**
   - 启动 A 侧算法对比材料，至少覆盖：
     - 单目标最短路径 vs 最短时间
     - 步行 vs 车辆/自行车过滤差异
     - 多目标状态压缩 DP 的适用规模与局限

**提交要求：**

- 更新 `tests/test_routing.py` 或新增独立演示/验证脚本，覆盖本周新增的策略对比样例。
- 输出一份 A 侧算法对比或演示说明草稿，可放在 `docs/` 或第十周工作进度目录。
- 提交 `工作进度/第十周/memberA第10周工作内容陈述.md`。

### 【成员 B：查找、排序、推荐与业务负责人】

**本周核心任务：**

1. **接入全文检索业务入口**
   - 在 `src/diary/` 或业务封装层中接入成员 C 提供的全文检索结果。

   - 至少保证 `success`、`message`、`query_type`、`total`、`filters`、`metadata`、`results` 等核心字段口径一致。

3. **模糊查询进一步增强**
   - 在第九周轻量匹配基础上，优先尝试：
     - 类别/业务关键词同义词归一化
     - 拼音缩写或首字母的最小可用支持
   - 若本周不实现编辑距离，需在工作陈述中明确原因和后续方案。

4. **第十周演示入口扩展**
   - 更新 CLI 或新增周演示脚本，至少覆盖：
     - 日记全文检索
     - 检索结果排序与展示
     - 从命中的校园日记结果进入路径规划提示
     - 场所/美食主链路未回退

5. **与 C 侧压缩接口预对接**
   - 明确压缩模块本周是在独立命令层演示，还是已经需要在业务层提供压缩/解压入口。
   - 如本周只做到最小演示，也要给出后续如何接入用户日记管理模块的接口草案。

**提交要求：**

- 更新 `src/search/`、`src/recommend/`、`src/diary/` 中对应业务代码。
- 补充或更新 `tests/test_search.py`、`tests/test_recommend.py`、`tests/test_diary.py`。
- 提交 `工作进度/第十周/memberB第10周工作内容陈述.md`。

     - 多关键词或多词项基础检索
     - 压缩后解压一致
     - 日记全文检索结果进入路径规划

**提交要求：**

- 提交 `工作进度/第十周/memberC第10周工作内容陈述.md`。

本周推荐演示链路：

1. 输入日记正文关键词，展示全文检索结果、命中词和基础排序。
2. 对命中的校园日记结果，读取 `destination_node_id`，展示从 `gate_north` 到目标节点的路径规划结果。
3. 对一段日记正文执行哈夫曼压缩与解压，展示原文、压缩结果长度和解压校验结果。
4. 再次执行场所查询或美食推荐演示，确认第九周主链路未回退。
5. 展示至少一组路径策略对比样例，例如最短距离 vs 最短时间，或步行 vs 自行车/车辆。

## 5. 提交形式与流程

### 代码与文档提交

- **主链路稳定优先**：第十周新增功能不得破坏第九周已经通过的业务链路和测试。
- **接口先对齐再接入**：成员 C 的全文检索和压缩返回结构在接入成员 B 之前，需先明确最小字段集。
- **标准数据优先**：继续以 `data/global_sites.json`、`data/sites/{site_id}/`、`data/diary_data.json` 为默认数据源，历史兼容数据不得重新变成主入口。
- **文档同步**：如新增索引缓存、压缩产物、接口字段或演示命令，必须同步更新 `docs/数据字典.md` 或相关设计文档。

### 工作陈述提交

- **截止时间**：本周日（5月10日）20:00 前。
- **命名规范**：`memberX第10周工作内容陈述.md`。
- **最低内容**：本周完成事项、涉及文件、测试命令与结果、当前限制、后续计划、可演示命令。

### 周报准备

- 第十周周报需开始体现 **“从 M2 向 M3 过渡”** 的阶段特征，不能只写“功能已完成”，还需要记录：
  - 全文检索是否已接入业务层
  - 压缩模块当前完成到哪一步
  - 算法对比材料是否已开始沉淀
  - 当前阻塞是否会影响第十一、十二周联调

## 6. 大总管提醒

1. **第十周不是简单延续第九周演示，而是开始补课程设计的硬指标。** 全文检索和无损压缩不是加分项，是后续验收必须面对的功能。
2. **本周允许先做“基础版”，但必须可运行、可测试、可说明。** 不要一开始就把目标定成复杂中文分词、完整离线索引或高阶压缩容器，先把最小闭环做出来。
3. **M2 已经过线，不代表可以放松接口纪律。** 新增字段优先追加，已有输入输出协议不要随意改。
4. **文档沉淀要提前开始。** 第十二周之后再补算法对比、测试记录和演示说明，风险会很高。
