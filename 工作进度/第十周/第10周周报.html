第十周工作周报（5月4日 - 5月10日）

项目名称：智能校园/景区导览系统
汇报人：项目大总管 (Member A)

本周团队核心目标为“M3 联调能力预热与离线检索落地”。在第九周完成 M2 业务覆盖和期中展示收口后，本周已补齐课程设计中的全文检索、无损压缩/解压、统一输出深化、最小可演示 Web UI 与算法对比初稿，并继续保证“查询/推荐 -> 真实距离 -> 路径规划”主链路未回退。当前系统已经具备“日记全文检索 -> 命中结果 -> 目的地节点 -> 路径规划”“日记正文压缩 -> 解压校验”以及“本地 Web 页面统一演示查询、推荐、日记和路径”的最小可演示闭环。

以下是本周各成员的工作总结、验收结论及后续计划：

1. 团队整体进展概览

  • Member A (算法与图结构)：✅ 已完成路径展示字段增强、标准图策略对比样例整理、交通方式差异验证和“日记结果 -> 路径规划”链路可路由性检查。
  • Member B (业务与推荐/UI)：✅ 已完成全文检索业务接入、统一响应结构深化、模糊查询同义词/首字母增强、--week10 CLI 演示入口扩展和最小可演示 Web UI 初版。
  • Member C (数据与检索/压缩)：✅ 已完成倒排索引全文检索基础版、哈夫曼压缩/解压基础版、离线索引预留入口、对应测试与数据字典同步。

2. 本周核心收口成果

  1. 全文检索能力落地：标准 data/diary_data.json 已可支持单关键词、多关键词和别名词的日记正文检索，返回 diary_id、title、matched_terms、score、destination_node_id 等字段。
  2. 压缩模块最小闭环完成：当前已能对样例日记正文执行哈夫曼压缩、解压和一致性校验，并输出原文大小、位流大小与估算压缩包大小。
  3. 业务层统一输出继续收口：场所查询、美食推荐、日记基础查询、日记全文检索已统一到 success、message、query_type、filters、metadata、results 这一套响应口径。
  4. M2 主链路未回退：场所查询、美食推荐、真实距离排序和路径规划接口继续保持可运行，且第十周新增能力没有破坏第九周演示入口与集成测试。
  5. 最小可演示 Web UI 初版完成：本地 Web 入口已覆盖站点概览、景点查询、场所查询、美食推荐、日记全文检索、路线规划、地图高亮和室内路径步骤说明。
  6. M3 预热材料开始沉淀：A 侧已形成第十周算法对比说明，C 侧已形成检索与压缩验证记录，B 侧已形成第十周业务接入与 UI 展示说明。

本周主要成果：

5. 当前限制与处理口径

  1. 全文检索仍为基础版：当前未实现复杂中文分词、TF-IDF/BM25、短语查询或布尔查询，排序以轻量覆盖度加权为主。
  2. 压缩模块仍为内存级结构：当前已能完成压缩/解压和体积估算，但还不是最终的落盘压缩容器格式。
  3. 离线索引暂未持久化到磁盘：offline_index.py 当前只提供运行时草稿包，用于验证调用边界与恢复正文逻辑。
  4. 缺失 destination_node_id 的日记结果按展示降级处理：业务层当前不会对这类结果强制提供路径提示，避免误导联调。
  5. Web UI 当前为最小可演示版本：第十周优先覆盖主链路展示，第十一周起继续补产品骨架、站点切换、日记中心、演示模式和验收脚本。
