# 软件开发任务描述

> 文档类型：软件开发任务描述（对应课程「应完成的文档资料」第 1 项）  
> 课程设计题目：个性化旅游系统的设计与实现

---

## 一、任务背景

随着假期旅游需求的增长，用户在旅游全流程中面临信息分散、路线规划低效、离线场景体验差等痛点。现有商业地图与旅游应用主要面向宏观城市道路导航，难以覆盖大型封闭园区（景区、校园）内的微观寻路需求，也缺乏对个人兴趣的深度适配与弱网环境下的离线支持。

本课程设计任务是在上述背景下，设计并实现一套**基于自研数据结构与核心算法**的个性化旅游系统，覆盖旅游前、旅游中、旅游后的完整使用场景，并在系统开发过程中引入智能体辅助工程化实践。

---

## 二、系统目标

开发一套真实可运行的个性化旅游系统，具体目标如下：

1. 帮助用户在旅游前根据热度、评价和个人兴趣选择旅游目的地；
2. 帮助用户在景区或校园内规划最优游览路线，支持多种交通方式与室内外导航；
3. 帮助用户在游览过程中查询附近服务设施与美食；
4. 支持用户记录、分享和检索旅游日记；
5. 所有核心功能均基于自研数据结构与算法实现，并提供多算法对比分析。

---

## 三、数据规模要求

| 指标 | 最低要求 |
|------|----------|
| 景区与校园数量 | ≥ 200 个 |
| 每处建筑物数量 | ≥ 20 个（景点、教学楼、办公楼、宿舍等） |
| 服务设施种类 | ≥ 10 种（商店、饭店、洗手间、图书馆、食堂、超市、咖啡馆等） |
| 服务设施总数 | ≥ 50 个 |
| 道路图边数 | ≥ 200 条（尽量贴近真实景区与校园） |
| 系统用户数 | ≥ 10 人 |

数据来源采用“**1 个深度导航核心站点 + 200+ 推荐/查询对象**”的混合策略：1 个核心景区/校园用于室内外导航、多目标路径和地图展示，200+ 景区/校园对象用于推荐、查询和排序规模达标；由成员 C 负责维护数据字典、用户样例、规模核验记录与版本管理。

## 四、功能需求

### 4.1 旅游推荐

- 按热度、评价、个人兴趣推荐景点与学校；
- 支持按名称、类别、关键字查询，查询结果可按热度与评价排序；
- **核心算法**：Top-K 推荐（最小堆/快速选择，避免全量完全排序）、排序算法；
- **创新点**：支持用户自定义多维度权重（如热度 40% + 评分 30% + 距离 30%）的加权融合排序；支持错别字容错、拼音首字母、同义词等模糊查询增强。

### 4.2 旅游路线规划

- 单目标最优路线：从当前位置到指定景点或场所；
- 多目标路线：从当前位置出发，访问多个目标点后返回起点；
- 支持图形化地图展示与路径高亮；
- **路线策略**：
  - 最短距离策略；
  - 最短时间策略（考虑拥挤度，真实速度 = 拥挤度 × 理想速度）；
  - 交通工具约束策略（校区：步行/自行车；景区：步行/电瓶车；支持混合交通工具）；
  - 室内导航策略（大门→电梯→楼层→房间）；
- **核心算法**：Dijkstra 最短路径、状态压缩动态规划（多目标回路）、多层图建模；
- **创新点**：引入时间维度动态边权（4D 时空动态权值），实现智能避峰与路线动态自适应规划；室内外跨层一体化图结构，支持多交通工具无缝切换。

### 4.3 场所查询

- 选中景点或场所后，查询一定范围内的服务设施，按**真实路径距离**排序（禁止使用直线距离）；
- 支持按类别过滤；
- 支持输入类别名称查找附近设施；
- **核心算法**：查找算法、排序算法（基于图上最短路径距离）。

### 4.4 旅游日记管理

- 用户可创建、编辑、删除旅游日记，并通过文字、图片、视频记录旅游内容；
- 统一管理所有用户日记，浏览量作为热度指标；
- 用户可对旅游日记评分，支持按热度、评分、个人兴趣推荐日记；
- 图片和视频在第 13 周前至少提供本地样例与占位展示，保证验收时可演示；
- **核心算法**：排序算法（Top-K）。

### 4.5 旅游日记交流

- 按目的地检索相关日记，并按热度与评分排序；
- 支持日记标题精确查询（适应大规模、高动态数据）；
- 支持日记内容全文检索；
- 支持日记无损压缩存储；
- 支持基于 AIGC 的旅游动画生成（根据照片与文字描述，至少提供轻量可演示输出，如模板化动画、分镜页或 GIF）；
- **核心算法**：查找算法、倒排索引全文检索、哈夫曼无损压缩；
- **创新点**：在压缩后的本地数据上构建倒排索引，支持完全断网时的高效全文检索；高优离线同步机制，预先打包高价值数据保障弱网体验。

### 4.6 美食推荐

- 按热度、评价、距离排序，支持菜系过滤；
- 支持 Top-10 推荐（不经过全量完全排序）；
- 支持名称、菜系、饭店等模糊查询，查询结果可多关键字排序；
- **核心算法**：Top-K 排序（最小堆）、模糊查找算法。

## 五、系统架构

系统采用分层架构，核心算法模块与 UI 解耦；表现层以本地 Web 应用为主入口，CLI 作为调试和回归兜底入口：

```
表现层（UI / 命令行）
    ↓
业务层（成员 B：查询、排序、推荐、日记业务编排）
    ↓
算法层（成员 A：图建模与路径规划）
    ↓
数据层（成员 C：结构化数据集、全文检索、压缩）
```

**模块依赖关系**：
- 成员 C 提供结构化数据集 → 成员 A 建图寻路、成员 B 业务算法；
- 成员 A 提供真实距离与路径接口 → 成员 B 场所/美食距离排序；
- 成员 C 提供倒排索引检索结果 → 成员 B 日记全文检索展示。

## 十、创新点总结

1. **面向微观场景的时空动态多目标导航引擎**：建立室内外多层级拓扑网络，引入时间维度动态边权，结合状态压缩 DP 与改进 Dijkstra 实现智能避峰路线规划，填补现有商业地图在封闭园区微观导航上的空白。

2. **弱网环境下的高密度离线检索与存储框架**：基于哈夫曼树对海量中文游记进行无损压缩，并在压缩后的本地数据上构建倒排索引，实现完全断网时的高效全文检索，解决偏远景区信息断层问题。

3. **可配置多目标加权推荐与模糊查询增强**：支持用户自定义热度、评分、距离等维度权重的融合排序；支持错别字容错、拼音首字母、同义词联想等模糊查询，提升真实用户输入场景下的检索命中率。
