## 二、总体结构

系统采用**四层分层架构**，核心算法模块与 UI 解耦，表现层以本地 Web 应用为主入口，CLI 作为兜底和回归入口，便于三人并行开发与独立测试。

```
表现层（UI / 命令行）
    ↓
业务层（成员 B：查询、排序、推荐、日记业务编排）
    ↓
算法层（成员 A：图建模与路径规划）
    ↓
数据层（成员 C：结构化数据集、全文检索、压缩）
```

**数据流向**：
- 成员 C 数据层 → 成员 A 建图 + 成员 B 业务算法
- 成员 A 距离/路径接口 → 成员 B 场所/美食距离排序
- 成员 C 全文检索结果 → 成员 B 日记全文检索展示

## 三、模块划分

### 3.1 模块总览

| 模块 | 负责成员 | 代码目录 | 说明 |
|------|----------|----------|------|
| UI 与演示 | B | `src/ui/` | 本地 Web 主入口、站点选择器、查询/推荐/路径结果展示、演示模式 |

| 推荐与排序 | B | `src/recommend/` | Top-K 堆、加权融合排序 |

| 数据集 | C | `data/` | JSON 数据文件与数据字典 |
| 测试 | C 主导 | `tests/` | 单元测试、集成测试 |
| 文档 | C 主导 | `docs/` | 设计文档、周报、验收材料 |

## 四、接口约定

### 4.1 成员 B ← 成员 A：距离查询接口

> 注：以下接口字段为当前草案，需三人在第一轮联调前确认（参见成员 B 开发计划第 8.1 节待确认事项）。

**请求**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `site_id` | string | 所在园区 ID |
| `start_node_id` | string | 起点节点 ID |
| `target_node_id` | string | 终点节点 ID |
| `strategy` | string | `shortest_distance` / `shortest_time` |
| `transport_mode` | string | `walk` / `bike` / `cart` / `mixed` |

**响应**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `success` | bool | 是否可达 |
| `distance` | float | 路径距离（米） |
| `estimated_time` | float | 预计时间（分钟） |
| `path_nodes` | list | 途经节点 ID 序列 |

### 4.2 成员 B ← 成员 C：基础数据与全文检索

- 业务实体统一字段：`id`、`name`、`category`、`site_id`、`node_id`、`heat`、`rating`、`tags`
- 全文检索响应：`{ query, results: [{ diary_id, title, matched_terms, score }] }`

### 4.3 UI 入口与数据契约

Web UI 统一通过一个轻量 bootstrap 接口拿到页面初始状态，再调用各业务接口完成查询与演示：

- `GET /api/bootstrap`
  - 返回站点列表、默认站点、起点候选、路线目标、地图边界、预设演示入口、统计信息和课程要求覆盖摘要。
- `POST /api/search/scenic`
  - 综合查询与推荐入口，承接景点/学校查询结果展示。
- `POST /api/search/places`
  - 场所查询入口，返回真实距离排序结果。
- `POST /api/recommend/catering`
  - 美食推荐入口，返回按热度、评分、距离和菜系筛选的结果。
- `POST /api/diaries/fulltext`
  - 日记全文检索入口，供日记中心和演示模式使用。
- `POST /api/diaries/save`
  - 日记创建 / 编辑入口，统一保存标题、正文、标签、媒体占位和目的地字段。
- `POST /api/diaries/rate`
  - 日记评分入口，同时更新展示用评分统计。
- `POST /api/diaries/aigc-preview`
  - AIGC 轻量演示入口，根据图片和文字生成模板化动画预览、分镜页或 GIF。
- `POST /api/route`
  - 单目标路径规划入口，返回路径摘要、逐步说明和 UI 高亮所需数据。
- `POST /api/route/multi`
  - 多目标路径规划入口，返回访问顺序、拼接路径和总距离 / 总时间摘要。

UI 页面状态约定：

- 第 13 周前六大功能入口必须全部能从 Web UI 直接触达。
- 切换站点后，当前查询、当前路线和高亮状态都应重置。
- 日记中心以“列表 + 详情 + 检索”三块组成，文本为主，图片/视频字段先占位。
- 演示模式保留固定的预设参数，方便验收时连续演示主链路。
- AIGC 动画生成允许采用轻量实现，但必须输出真实可见结果，不能只停留在方案说明。
