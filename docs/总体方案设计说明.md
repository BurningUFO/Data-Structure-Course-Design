# 总体方案设计说明

> 文档类型：总体方案设计说明（对应课程「应完成的文档资料」第 3 项）
> 课程设计题目：个性化旅游系统的设计与实现
> 最终产品定位：智能校园/景区导览系统
> 文档状态：最终产品设计方案同步版

---

## 一、项目定位

本项目最初按「个性化旅游系统」课程题目立项，最终产品收束为一套面向校园、景区等封闭或半封闭微观场景的**智能校园/景区导览系统**。系统覆盖出行前的目的地和美食推荐、出行中的地图导览与室内外路线规划、出行后的日记管理、交流、检索、压缩和 AIGC 轻量预览。

最终产品不是只展示算法命令行结果，而是以本地 Web UI 为主入口，通过稳定 API 串联地图、查询、推荐、路线、日记和演示功能。当前交付口径为：

- `PKU` 作为深度导航核心站点，包含真实地图层、室内外一体化路线、20 栋室内建筑入口和较完整的本地 OSM 派生数据。
- `THU`、`WHU`、`HZAU` 等 20 个扩展校园拥有实体 `data/sites/<SITE_ID>/` 数据目录，支持站点切换、地图、查询、推荐、路线和 5 栋室内建筑入口演示。
- `data/global_sites.json` 注册 200 个可用站点；无实体目录的站点通过 `template_clone` 复用模板校园图和课程图配置，对外保持自己的 `site_id`、学校名称和展示文本。
- Web 主入口默认运行在 `http://127.0.0.1:8765`，启动命令为 `py -m src.ui.demo_server` 或等价 Python 命令。

## 二、最终系统架构

系统采用「表现层 - 服务层 - 业务层 - 算法层 - 数据层」的分层架构。核心算法与 UI 解耦，服务层负责站点隔离和接口编排。

```text
表现层 Web UI
  src/ui/static/index.html
  src/ui/static/app.js
  src/ui/static/styles.css
        ↓
服务层 HTTP API / DemoUIService
  src/ui/demo_server.py
  src/ui/demo_service.py
        ↓
业务层 查询、推荐、日记、AIGC 编排
  src/search/
  src/recommend/
  src/diary/
        ↓
算法层 图建模、路线规划、全文检索、压缩
  src/graph/
  src/routing/
  src/compress/
        ↓
数据层 多站点注册与分层图数据
  data/global_sites.json
  data/sites/<SITE_ID>/
  data/users.json
  data/diary_data.json
```

### 2.1 站点隔离与模板复用

`data/global_sites.json` 是全局站点注册表，当前注册 200 个可用站点。每个站点对外使用自己的 `id`、`name`、`location`、`data_status`、`map_profile` 和 `sub_graphs`。

站点分为三类：

| 类型 | 代表 | 数据来源 | 地图表现 |
|------|------|----------|----------|
| 深度真实站点 | `PKU` | `data/sites/PKU/` + `data/sites/PKU/geo/` | 真实瓦片底图、本地 OSM 图层、室内外一体路线 |
| 实体扩展站点 | `THU`、`WHU`、`HZAU` 等 20 校 | 独立 `data/sites/<SITE_ID>/` | 本校课程图、真实瓦片底图、5 栋室内建筑入口 |
| 模板复用站点 | `USTC`、`BNU` 等 | `template_site_id` 指向模板站点 | 模板校园图，不加载真实底图和 OSM 上下文图层 |

模板复用站点不复制实体数据目录，而是通过 `src/site_registry.py` 解析 `template_site_id`，让图数据、搜索记录、推荐距离和路线计算复用模板站点。展示层通过 `display_overrides` 覆盖节点名、用户名和路线文本，保证 UI 和 API 响应仍显示当前站点名称，不把模板学校名泄漏给用户。

### 2.2 服务层职责

`DemoUIService(site_id)` 是 Web UI 的统一服务对象，负责：

- 加载当前站点图数据、搜索记录、用户样例、日记样例和 AIGC 样例；
- 构造 `/api/bootstrap` 初始状态，包括站点列表、地图能力、控件选项、演示预设、用户和统计信息；
- 将室外节点和边转换为 GeoJSON FeatureCollection；
- 为查询、推荐、日记、压缩、AIGC、单目标路线和多目标路线提供统一响应结构；
- 在模板站点中限制真实底图和 OSM 图层，避免数据口径误导。

## 三、地图与导航设计

地图方案是最终产品中变化最大的部分。早期 SVG 示意图已保留为兜底，正式展示层改为 Leaflet + GeoJSON + 本地 OSM 派生数据。

### 3.1 室外地图渲染

Web 前端保留稳定入口：

```text
renderMap()
renderSvgMap()
renderLeafletMap()
ensureLeafletMap()
syncLeafletRouteLayer()
fallbackToSvgMap()
```

`renderMap()` 根据 `map_renderer` 和 `map_capabilities` 在 `simple_svg` 与 `leaflet_geo` 之间切换。默认渲染器为 `leaflet_geo`，当 Leaflet 初始化、GeoJSON 加载或瓦片加载出现异常时，前端自动回退到 `simple_svg`。

Leaflet 运行时资源已本地化：

```text
src/ui/static/vendor/leaflet/
```

GeoJSON 数据由 `GET /api/map/geojson?site_id=...` 提供，符合 RFC 7946 坐标顺序 `[lng, lat]`：

- 节点为 `Point`，属性包含 `kind=node`、`id`、`name`、`category`、`category_label` 等字段；
- 边为 `LineString`，属性包含 `kind=edge`、`from`、`to`、`name`、`edge_type`、`distance_m`、`geometry_source` 等字段；
- 当前 PKU 运行时 GeoJSON 统计为 1090 个节点、1274 条边、2364 个 Feature，边 geometry 覆盖率为 100%，其中 1163 条为 OSM 匹配几何，111 条为人工/接驳几何。

### 3.2 真实底图与本地 OSM 图层

地图能力由 `/api/bootstrap` 中的 `map_capabilities` 描述：

- `basemaps.default=real_map` 的站点使用本地瓦片代理加载 OpenStreetMap / CARTO 瓦片，并带有明确 attribution；
- 瓦片代理接口为 `GET /api/map/tile/<source>/<z>/<x>/<y>.png`，服务端添加 User-Agent 并做 7 天缓存；
- `GET /api/map/osm-layers?site_id=...` 返回本地 `data/sites/<SITE_ID>/geo/` 下的道路、建筑、水域和绿地图层；
- 网络或瓦片源不可用时，前端可切换到 `none` 无底图模式，仍保留本地 GeoJSON 道路、POI 和路线展示。

模板复用站点的 `map_profile=template_clone`，`basemaps.default=none`，并且 `/api/map/osm-layers` 返回空 FeatureCollection，明确说明其为模板校园图，不声明真实 OSM 上下文数据。

### 3.3 室内地图与跨层导览

室内数据存放在 `data/sites/<SITE_ID>/indoor_*.json`。`GraphLoader.load_site_graph(site_id)` 会将 `outdoor.json` 和室内图合并为一张分层图，并为室外建筑入口与室内入口节点补充双向 `gate_link`。

前端通过 `GET /api/map/indoor?site_id=...&building_id=...&floor=...` 加载室内平面图。室内视图支持：

- 楼层切换；
- 房间、走廊、墙体、门洞、设施图标渲染；
- 室内功能区选择；
- 室内路线高亮；
- 室外路线与室内楼层视图切换。

PKU 支持 20 栋室内建筑入口，实体扩展校园支持 5 栋室内建筑入口，模板复用站点继承其模板站点的室内能力。

## 四、核心功能设计

### 4.1 路线规划

路线规划由 `src/graph/` 和 `src/routing/` 实现。

- 图结构使用邻接表：`Graph.nodes` 保存节点属性，`Graph.adj` 保存出边列表。
- `GraphLoader.load_site_graph(site_id)` 读取站点分层 JSON，合并室外、室内和 `gate_link`。
- `Router.query_routing(...)` 使用优先队列优化的 Dijkstra，支持 `shortest_distance` 和 `shortest_time`。
- `shortest_time` 使用 `distance / (speed * congestion)` 作为边权，兼容拥挤度和理想速度字段。
- 交通方式支持 `walk`、`bike`、`mixed`；`mixed` 会在每条可通行边上选择步行或骑行中预计时间更短的方式，室内边和 `gate_link` 强制步行。
- `Router.query_multi_target(...)` 先预计算点对点最短路，再用状态压缩 DP 求访问顺序，当前限制为 12 个及以下目标点。

路线响应保留路径节点、路径步骤、分层段、总距离、预计时间、交通方式、跨层摘要和 UI 所需 route GeoJSON。不可达时返回失败信息，不伪造路径。

### 4.2 查询、推荐与场所搜索

查询推荐由 `src/search/` 和 `src/recommend/` 实现。

- `src/recommend/topk.py` 实现自定义小顶堆 `MinHeap`，Top-K 复杂度为 `O(n log k)`，用于景点、学校、美食和日记推荐。
- 加权排序支持热度、评分、真实路径距离三维归一化，默认权重为热度 40%、评分 30%、距离 30%。
- 兴趣推荐支持静态用户兴趣和动态 `interest_profile`，将兴趣匹配、热度、评分和可选距离融合为可解释 `recommendation_score`。
- 模糊查询支持同义词、英文/拼音缩写、标点归一化、有序跳字缩写和保守编辑距离。
- 场所查询支持中心点、类别、半径和真实路径距离排序，距离来自图上最短路径，而非直线距离。
- 餐饮推荐支持菜系推断、菜系过滤、关键词过滤、热度/评分/距离排序和 Top-K 输出。

### 4.3 日记、全文检索、压缩与 AIGC

日记模块由 `src/diary/`、`src/compress/` 和 `src/ui/demo_service.py` 协作实现。

- 日记中心支持列表、推荐、全文检索、创建、编辑、删除、浏览量更新和评分；
- 日记全文检索使用倒排索引，采用轻量 CJK n-gram 分词，支持中文关键词、多关键词、同义词和片段摘要；
- 哈夫曼压缩实现字符频率统计、哈夫曼树、编码表、bit 打包、解压和回环校验；
- `/api/diaries/compress` 返回原文字节数、bit 长度、估算压缩包大小、压缩率和 `roundtrip_ok`；
- `/api/aigc/preview` 默认提供本地模板化分镜 / GIF 可见输出；当用户配置 `OPENAI_API_KEY` 并选择实时模式时，可调用图片生成接口生成分镜，失败时自动回退到本地模板预览。

## 五、稳定接口契约

最终产品不再使用早期分散 CLI 作为主入口，Web UI 通过以下稳定 API 访问系统能力。后续扩展只允许追加字段，不应删除、重命名或改变既有字段含义。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/bootstrap` | 页面初始状态、站点列表、地图能力、控件、统计和演示预设 |
| GET | `/api/map/geojson?site_id=...` | 当前站点室外节点和边的 GeoJSON FeatureCollection |
| GET | `/api/map/osm-layers?site_id=...` | 本地 OSM 派生道路、建筑、水域和绿地图层 |
| GET | `/api/map/indoor?...` | 室内建筑指定楼层平面图 |
| GET | `/api/map/tile/<source>/<z>/<x>/<y>.png` | 带缓存的真实瓦片代理 |
| POST | `/api/search/scenic` | 综合查询、兴趣推荐和加权排序 |
| POST | `/api/search/places` | 场所查询、附近设施和真实距离排序 |
| POST | `/api/recommend/catering` | 餐饮推荐和菜系过滤 |
| POST | `/api/diaries/*` | 日记列表、推荐、全文检索、CRUD、评分、压缩预览 |
| POST | `/api/aigc/preview` | AIGC 模板/实时分镜预览 |
| POST | `/api/route` | 单目标路线规划 |
| POST | `/api/route/multi` | 多目标路线规划 |

## 七、最终创新点落地

1. **真实微观地图与室内外一体导航**
   系统从 SVG 示意图升级为 Leaflet + GeoJSON + 本地 OSM 派生数据，并保留 SVG fallback。路线规划不只输出节点序列，还能在地图上高亮真实/接驳几何，并支持室外到室内楼层的跨层导览。

2. **多校园站点隔离与 200 站点模板扩展**
   系统用 `global_sites.json` 注册 200 个站点，用实体目录和 `template_clone` 两种方式兼顾数据深度与规模要求。模板站点复用图数据但重写展示文本，保证 API 与 UI 对外仍是当前站点。

3. **可解释个性化推荐闭环**
   推荐排序不只看热度，还融合评分、真实路径距离、静态兴趣和动态兴趣画像，并在结果中输出兴趣命中、权重贡献和推荐理由。

4. **弱网离线检索与压缩演示**
   日记内容通过倒排索引支持本地全文检索，哈夫曼压缩提供无损压缩和回环校验。即使没有外部服务，日记检索、压缩摘要和 AIGC 模板预览仍可展示。

5. **课程算法工程化落地**
   系统覆盖图、邻接表、优先队列、堆、排序、哈希/索引、倒排索引、哈夫曼树、状态压缩 DP 等数据结构与算法，并通过 API、UI 和测试材料形成可复核证据链。

## 八、验证与边界

最终产品采用以下验证口径：

- `py -m pytest -q` 作为全量回归建议命令；
- API 回归覆盖 bootstrap、GeoJSON、查询、推荐、路线、多目标路线和日记能力；
- UI 冒烟覆盖站点切换、地图显示、路线高亮、室内入口、查询推荐和模板站点不加载真实底图；
- 文档与演示材料区分 PKU 深度真实地图、20 个实体扩展校园和 200 站点模板复用，不夸大模板站点的真实道路精度。

已知边界：

- 真实地图精度以 PKU 最完整，扩展校园和模板校园主要用于课程演示与站点隔离验证；
- 运行时 UI/API 不直接调用 OSMnx 或 Overpass，真实地图数据通过离线准备脚本和本地文件进入系统；
- 多目标路线当前限制 12 个及以下目标点；
- AIGC 实时图片生成依赖外部 API 和环境变量，默认可见能力为本地模板分镜/GIF 预览。
