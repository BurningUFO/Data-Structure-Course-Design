# 提交信息模板

> 用途：统一团队的 Git 提交风格，方便后续整理周报、修改日志和验收材料。

## 推荐格式

```text
<类型>: <模块> - <简要说明>
```

## 类型建议

- `feat`：新增功能
- `fix`：修复问题
- `refactor`：重构
- `docs`：文档更新
- `test`：测试补充或调整
- `data`：数据更新
- `chore`：杂项维护

## 推荐示例

```text
feat: routing - add single-destination shortest path
feat: search - support fuzzy food query
fix: diary - handle empty rating list
docs: design - update route planning module notes
test: graph - add shortest path cases
data: scenic-map - import building and facility samples
```

## 提交正文模板

```text
<类型>: <模块> - <简要说明>

背景：
- 

本次改动：
- 
- 

测试：
- 

风险/待办：
- 
```

## 分支合并前检查清单

- 提交说明是否能看出改动范围
- 是否写清楚模块名
- 是否避免使用“update”“modify”“test”这类无信息量标题
- 是否已经在成员分支日志中登记本次提交
- 是否补了必要的测试或说明未测原因
