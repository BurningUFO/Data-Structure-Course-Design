## 1.1 M21 交通方式验收口径

- PKU 室外图已保留纯步行边，并补充南门至五四体育场、图书馆方向的步行 / 自行车共享白线边。
- `shortest_time` 支持 `walk`、`bike`、`mixed`：`mixed` 表示同一条路线可组合步行和自行车，并按总时间择优。
- 室内边和室内外 `gate_link` 仍按步行处理；自行车模式不会进入楼内。
- 固定演示路线：`gate_east -> parking_lot` 步行更优，`gate_south -> sports_ground` 自行车明显优于纯步行且 `mixed` 最快，`gate_south -> lib_reading_room_1` 可验证室外混合交通入楼后自动切回步行。

## 1.2 M23 个人兴趣推荐验收口径

- `data/users.json` 的 `interests` 已接入运行时推荐链路，Web 顶部提供“当前用户”和“当前兴趣偏好”选择入口。
- 综合查询的“按兴趣综合”排序融合 `interest_match_score`、`heat`、`rating` 和 `distance_m`，结果卡片展示兴趣分、综合分和命中来源。
- 日记中心新增“浏览 / 推荐日记”入口，和原全文检索入口并存；日记推荐融合 `interest_match_score`、`heat` 和 `rating`。
- 固定演示用户：`user_001`（校园、秋景、图书馆）优先推荐图书馆 / 校园学习相关结果；`user_002`（美食、食堂、校园生活）优先推荐农园食堂和食堂美食日记。

## 6. 第11周课程核验口径

本周新增 `tests/test_course_requirements.py` 作为课程硬指标核验入口。当前核验采用强断言方式：

- 强断言：`data/users.json` 用户数 `>=10`、日记独立作者数 `>=10`、必要课程文档存在、AIGC / 媒体占位样例存在。
- 强断言：扩展推荐 / 查询对象 `>=200`、PKU 服务设施口径节点 `>=50`、PKU 分层图边数 `>=200`。
- 数据质量断言：用户 / 节点 / 扩展对象 ID 唯一，边端点均存在，扩展对象保留至少 5 个可路由映射样例。
- 第 12 周目标：成员 A 补 200+ 边路径性能验证，成员 B 接 Web 日记 CRUD 和 AIGC 可见入口，成员 C 继续优化数据真实性和验收材料。
