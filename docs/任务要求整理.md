# 数据结构课程设计任务要求整理

## 1. 课题目标

本课程设计的题目是“基于智能体的个性化旅游系统的设计和开发”。项目不仅要求做出可用系统，还要求体现以下几点：

- 使用智能体辅助完成系统设计、开发、测试和文档工作。
- 核心考查点是数据结构与算法的设计、实现、分析和对比。
- 按软件工程流程完成需求分析、概要设计、详细设计、编码、测试和文档整理。
- 最终成果必须包含系统、报告、文档和过程材料。

## 2. 必须实现的系统能力

### 2.1 旅游推荐

- 根据热度、评价、个人兴趣推荐景点和学校。
- 支持按名称、类别、关键字查询。
- 查询结果支持排序。
- 核心算法：
  - 查找算法
  - 排序算法
  - Top-N 场景下不完全排序
  - 需要考虑数据动态变化

### 2.2 旅游路线规划

- 单目标最优路径规划。
- 多目标最优路径规划，且需要回到起点。
- 支持地图展示和路径展示。
- 需要覆盖以下策略：
  - 最短距离
  - 最短时间
  - 多交通工具下的最短时间
  - 室内导航
- 核心算法：
  - 最短路径
  - 多点路径规划

### 2.3 场所查询

- 查询某个地点附近一定范围内的设施。
- 支持按类别过滤。
- 支持按类别名称查找附近服务设施。
- 结果需要按距离排序。
- 重点要求：
  - 不能用直线距离代替真实路径距离
- 核心算法：
  - 查找算法
  - 排序算法

### 2.4 旅游日记管理

- 支持文字、图片、视频形式的日记记录。
- 支持统一管理所有用户日记。
- 支持浏览量和评分。
- 支持按热度、评价、兴趣推荐。
- 核心算法：
  - 排序算法

### 2.5 旅游日记交流

- 按旅游目的地查询并排序相关日记。
- 按日记名称精确查询。
- 支持全文检索。
- 支持无损压缩存储。
- 支持基于照片和文字描述生成旅游动画。
- 核心算法：
  - 查找算法
  - 排序算法
  - 文本搜索
  - 无损压缩

### 2.6 美食推荐

- 按热度、评价、距离排序。
- 支持按菜系过滤。
- 支持基于内容的模糊查询。
- Top-N 推荐不能依赖完全排序。
- 核心算法：
  - 模糊查找
  - 排序算法

## 3. 数据规模硬性要求

- 景区和校园总数不少于 200 个。
- 每个景区或校园中的建筑物不少于 20 个。
- 服务设施类别不少于 10 种，总数量不少于 50 个。
- 内部道路图边数不少于 200 条。
- 系统用户数不少于 10 人。

这部分是验收底线，建模和数据准备阶段必须先满足。

## 4. 文档与过程要求

最终至少要形成以下文档材料：

1. 软件开发任务描述
2. 功能需求说明与分析
3. 总体方案设计说明
4. 数据结构说明和数据字典
5. 各模块设计说明
6. 应用示例执行结果与测试说明
7. 评价和改进意见
8. 用户使用说明

课程材料还明确强调：

- 要持续积累文档，不是最后一次性补写。
- 建议在项目根目录维护 Markdown 文档。
- 每周需要提交周报。
- 第五周要讲解设计方案和大模型使用心得。

## 6. 对团队协作的直接影响

为了满足课程要求，仓库管理不能只靠口头同步，至少要做到：

- 每个成员有固定分支。
- 每次提交都记录任务、算法、测试和风险。
- `main` 分支保留项目级变更总览。
- 文档、代码、测试、演示材料同步推进。

## 7. 建议的仓库内交付物

建议在 `main` 分支长期维护以下内容：

- `docs/任务要求整理.md`：统一任务口径
- `docs/成员分支提交日志模板.md`：成员记录分支工作
- `docs/项目修改日志模板.md`：组长维护项目级变更
- `docs/提交信息模板.md`：统一提交信息格式

## 8. 当前最值得优先推进的事情

按课程要求和当前时间，优先级建议如下：

1. 明确 3 人分工和各自分支。
2. 确定系统范围和 MVP。
3. 先完成需求文档、功能列表和系统架构。
4. 尽快落地数据模型与核心算法选型。
5. 从最短路径、查找、排序、文本搜索等核心算法开始实现和对比。
6. 同步维护周报、设计说明和测试记录，避免后期补材料。
