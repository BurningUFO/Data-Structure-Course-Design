## 2. 全局景区列表: `global_sites.json`

记录所有已注册的景区（学校/景点）元信息。

```json
{
  "sites": [
    {
      "id": "PKU",
      "name": "北京大学",
      "description": "...",
      "location": "北京市海淀区...",
      "sub_graphs": ["outdoor", "indoor_LIB", "indoor_DORM1"]
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `sites` | `array` | ✅ | 景区列表 |
| `sites[].id` | `string` | ✅ | 全局唯一景区 ID，作为 `sites/{id}/` 文件夹名 |
| `sites[].name` | `string` | ✅ | 景区显示名称 |
| `sites[].description` | `string` | 否 | 景区描述 |
| `sites[].location` | `string` | 否 | 地理位置 |
| `sites[].sub_graphs` | `array` | ✅ | 该景区包含的子图文件名（不含 `.json`） |

## 3. 分层图数据格式

### 3.1 节点 (Nodes)

定义在 `sites/{site_id}/outdoor.json` 或 `indoor_XXX.json` 中。

```json
{
  "graph_id": "PKU_outdoor",
  "graph_type": "outdoor",
  "nodes": [
    {
      "id": "gate_north",
      "name": "北大西门",
      "type": "entrance",
      "is_gate": true,
      "sub_graph_id": null,
      "tags": ["校门"],
      "description": "...",
      "category": "entrance",
      "facilities": ["安保亭"],
      "open_hours": "06:00-22:00",
      "location": {"lat": 39.9929, "lng": 116.3055}
    }
  ]
}
```

#### 节点字段

| 字段 | 类型 | 必填 | 适用 | 说明 |
|------|------|------|------|------|
| `id` | `string` | ✅ | 全部 | 全局唯一节点 ID，**不允许跨图重复** |
| `name` | `string` | ✅ | 全部 | 节点显示名称 |
| `type` | `string` | ✅ | 全部 | 类型：`entrance`, `building`, `facility`, `landmark`, `intersection`, `hall`, `reading_room`, `staircase`, `elevator`, `service`, `dormitory` |
| `is_gate` | `bool` | ✅ | 全部 | 是否为门节点（层级间连接点） |
| `sub_graph_id` | `string\|null` | ✅ | 全部 | 门节点指向的子图 ID（如 `indoor_LIB`）；非门节点为 `null` |
| `tags` | `array` | 否 | 全部 | 标签，用于模糊搜索和分类推荐 |
| `description` | `string` | 否 | 全部 | 详细描述 |
| `category` | `string` | 推荐 | 全部 | 业务分类：`entrance`, `education`, `dormitory`, `catering`, `shopping`, `sports`, `landmark`, `restroom`, `parking`, `road`, `hall`, `reading_room`, `service`, `passage` |
| `facilities` | `array` | 否 | 全部 | 设施列表 |
| `open_hours` | `string` | 否 | 设施类 | 营业时间 |
| `location` | `object` | 否 | 全部 | `{"lat": 浮点数, "lng": 浮点数}` 经纬度 |
| `capacity` | `int` | 否 | 阅览室等 | 容量/座位数 |
| `is_indoor` | `bool` | 推荐 | 设施类 | 是否室内设施（Member B 查询洗手间时使用） |
| `indoor_building` | `string` | 条件 | 室内设施 | 所在建筑名称（`is_indoor=true` 时使用） |

### 3.2 边 (Edges)

```json
{
  "edges": [
    {
      "from": "gate_north",
      "to": "square_center",
      "distance": 80,
      "type": "outdoor_road",
      "congestion": 0.6,
      "ideal_speed": 1.5,
      "vehicle_access": "all",
      "name": "西门大道"
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `from` | `string` | ✅ | 起点节点 ID |
| `to` | `string` | ✅ | 终点节点 ID |
| `distance` | `float` | ✅ | 物理长度（米） |
| `type` | `string` | ✅ | 边类型：`outdoor_road`（室外道路）、`indoor_path`（室内走廊）、`elevator`（电梯）、`stairs`（楼梯） |
| `congestion` | `float` | 推荐 | 拥塞系数 (0~1 低拥塞, >1 高拥塞），默认 `1.0` |
| `ideal_speed` | `float` | 推荐 | 理想通行速度（米/秒），默认 `1.5` |
| `vehicle_access` | `string` | 推荐 | **Member A 交通工具过滤逻辑**：`all`（所有通行）、`pedestrian_only`（仅行人）、`vehicle_only`（仅车辆）；默认 `all` |
| `name` | `string` | 否 | 道路名称 |
| `description` | `string` | 否 | 补充说明 |

## 4. 跨模块数据依赖关系

### 4.0 用户样例数据: `data/users.json`

第十一周新增用户样例数据，用于满足课程要求中的 `>=10` 系统用户指标，并与日记作者字段保持一致。

```json
{
  "id": "user_001",
  "name": "张三",
  "role": "student",
  "interests": ["校园", "秋景", "图书馆"],
  "home_site_id": "PKU",
  "created_at": "2026-05-10"
}
```

| 字段 | 类型 | 必填 | 用途 |
|------|------|------|------|
| `id` | `string` | ✅ | 用户唯一 ID，应与日记 `author_id` 对齐 |
| `name` | `string` | ✅ | 用户展示名，应与日记 `author_name` 对齐 |
| `role` | `string` | 推荐 | 用户类型，如 `student`、`tourist` |
| `interests` | `array<string>` | 推荐 | 推荐和演示时的兴趣标签 |
| `home_site_id` | `string` | 推荐 | 默认关联站点，当前为 `PKU` |
| `created_at` | `string` | 推荐 | 样例用户创建日期 |

一致性要求：
- `diary_data.json` 中出现的 `author_id` 应能在 `users.json` 中找到。
- 第十一周核验口径要求 `users.json` 用户数 `>=10` 且日记独立作者数 `>=10`。

## 5. 补充说明

### 5.1 节点 ID 全局唯一
不同层级的节点 ID 不得重复。例如 `outdoor.json` 中的 `library` 和 `indoor_LIB.json` 中的 `lib_entrance` 是两个不同 ID，通过 `library.is_gate=true` 且 `library.sub_graph_id="indoor_LIB"` 来建立连接。

### 5.2 门节点命名规范
- 室外图的门节点名建议以建筑名命名（如 `library`, `canteen`），语义清晰
- 室内图入口节点建议以 `建筑名_entrance` 命名（如 `lib_entrance`），避免混淆

### 5.3 边的双向性
所有边需要同时存储双向（`from→to` 和 `to→from`），否则 Dijkstra 只能单方向搜索。

### 5.4 性能指标
- 推荐算法支持 Top-N 剪枝（默认 Top-10）
- 路径规划支持动态权重调整（通过 `congestion` 系数调节）
