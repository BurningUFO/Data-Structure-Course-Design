# 地图方案 B M32 多校园总验收收口报告

## 1. 总体验收结论

截至 2026-05-20，地图方案 B 的多校园扩展已完成 M31D 与 M32A-M32C 收口：`PKU` 基线站点和 20 个扩展校园均可通过统一入口完成站点切换、Leaflet 地图展示、室外路线、室内入口、综合查询、查附近、餐饮推荐和兴趣推荐演示。

本轮 M32C 仅整理课程答辩材料与扩站说明，不新增代码功能，不调用 OSMnx、Overpass、web search 或任何新的子 agent / Codex 子进程。

## 4. 答辩主线

1. 项目不是普通导航，而是面向校园/景区的微观导览系统。
2. 数据层用“全局站点注册 + 单站点分层图目录”实现多校园扩展。
3. 算法层覆盖分层图、Dijkstra、状态压缩 DP、Top-K 排序、倒排索引和哈夫曼压缩。
4. 服务层通过 `DemoUIService(site_id)`、`/api/bootstrap`、`/api/map/geojson`、`/api/route` 和 `/api/route/multi` 保持稳定 API 契约。
5. UI 层通过站点选择器、Leaflet 地图、查询推荐面板、路线面板和室内楼层面板串起完整演示。
6. 验收层用 M31D/M32A/M32B 专项测试和全量 pytest 证明 20 校站点隔离与核心链路稳定。

## 6. 最终运行与验证命令

```powershell
py -m src.ui.demo_server
```

默认访问：

```text
http://127.0.0.1:8765
```

最终回归建议：

```powershell
py -m pytest -q
```

若演示前需要避免命中旧服务，先检查端口：

```powershell
netstat -ano | findstr :8765
```

## 7. 收口边界

- 不在 M32C 新增地图数据、道路匹配、路由算法或 UI 功能。
- 不把 `output/`、`.codex_tmp/`、`.playwright-cli/`、`scripts/` 或 `data/sites/PKU/geo/pku_poi_overpass_raw.json` 等未跟踪产物纳入交付提交。
- 不修改稳定接口字段；若后续扩展，只允许追加字段或新增离线数据文件。
- 20 校模板数据已满足课程演示和扩站流程说明；真实道路几何增强应作为后续离线数据工程单独排期。
